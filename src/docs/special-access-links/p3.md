# Phase 3 — Let a link-holder read and write a claim's proofs

Prerequisite: phase 2 complete. Gate: `npm run gate`, plus `npm run gate:openapi` for steps 3.4 and 3.5.

This is use case 2 of `special-access-check.md` for page 1 (`/incident/:incidentId/proofs`): the
link-holder may read the claim, read the apartment's assets, and **post the photos** — the claim's
evidence writes. It is wider than the blockers doc's B4, which named only the reads; the code-level
change is the same guard swap plus one new bind kind (D19).

No handler changes. `resolveOwnedIncident` and `requireItem` keep asserting apartment ownership and
keep refusing a filed claim; they simply see the impersonated owner, which is exactly how the
token path is designed to work.

Decisions in play: D11, D12, D13, D19, D20.

## Step 3.1 — The `incidentParam` bind kind

**Touch:** `src/middleware/specialAccessGuard.ts`

**Do (a) — the union.** Replace the `AccessBind` declaration and its doc comment with:

```ts
/**
 * Where a route's protected target lives, and therefore what the grant must
 * match. Named explicitly per route because the routes disagree on their param
 * name (`/apartments/{id}` vs `/apartment-shots/apartment/{apartmentId}`), so an
 * implicit "find an id" resolver would be wrong on half of them (D11).
 *
 * `incidentParam` is the one kind that needs a read of its own: an incident id is
 * not a reservation id, so the guard resolves the incident's `reservationId` and
 * compares that. Binding such a route by `apartmentParam` instead would match the
 * grant's apartment while letting a link scoped to ONE reservation open a claim
 * for a different stay in the same apartment — which is precisely the narrowing
 * `targetMatches` exists to preserve.
 */
export type AccessBind =
  | { kind: "reservationParam"; param: string }
  | { kind: "apartmentParam"; param: string }
  | { kind: "incidentParam"; param: string }
  | { kind: "reservationBody"; field: string };
```

**Do (b) — pass the database in.** The call site inside the middleware body changes from:

```ts
    if (!(await targetMatches(c, grant, opts.bind))) {
```

to:

```ts
    if (!(await targetMatches(c, grant, opts.bind, db))) {
```

**Do (c) — the resolver.** In `targetMatches`, insert the new branch between the `apartmentParam`
branch and the `let body:` line, and add the `db` parameter:

```ts
async function targetMatches(
  c: { req: { param: (name: string) => string | undefined; raw: Request } },
  grant: { reservationId: string | null; apartmentId: string },
  bind: AccessBind,
  db: Variables["db"],
): Promise<boolean> {
  if (bind.kind === "reservationParam") {
    return c.req.param(bind.param) === grant.reservationId;
  }

  if (bind.kind === "apartmentParam") {
    return c.req.param(bind.param) === grant.apartmentId;
  }

  if (bind.kind === "incidentParam") {
    const incidentId = c.req.param(bind.param);

    if (!incidentId) return false;

    const reservationId = await specialAccessService.resolveIncidentReservation(
      db,
      incidentId,
    );

    return reservationId !== null && reservationId === grant.reservationId;
  }

  let body: Record<string, unknown>;
```

Add one sentence to the existing `targetMatches` doc comment, after "Path params are always
available here.":

```
 * `incidentParam` is the exception: it costs one indexed read of `incidents` to
 * turn the param into a reservation id, paid only on the token path.
```

**Do (d) — the import.** Change `import { App } from "@/types";` to:

```ts

```

## Step 3.2 — The lookup the guard needs

**Touch:** `src/modules/special_access/special_access.service.ts`

**Do:** Add this method to `specialAccessService`, immediately after `resolveApartmentOwner`:

```ts
  /**
   * The reservation an incident belongs to, for the guard's `incidentParam` bind.
   *
   * `null` for an unknown incident, which the guard treats as a mismatch rather
   * than a 404: the token is validated before any target is trusted, so an
   * unknown incident must be indistinguishable from one belonging to somebody
   * else's reservation.
   */
  async resolveIncidentReservation(
    db: Variables["db"],
    incidentId: string,
  ): Promise<string | null> {
    const [row] = await db
      .select({ reservationId: incidents.reservationId })
      .from(incidents)
      .where(eq(incidents.id, incidentId))
      .limit(1);

    return row?.reservationId ?? null;
  },
```

`incidents` and `eq` are already imported in this file — do not add imports.

  here; step 3.3 covers the behaviour at the guard).
