# Phase 2 — Make the contract say what the code already does

Prerequisite: phase 1 complete. Gate: `npm run gate`, plus `npm run gate:openapi` for steps 2.1,
2.2 and 2.6.

No behaviour changes. Every route's runtime behaviour is identical before and after; what changes
is that the **document** — which is the frontend's entire contract, since it runs
`npm run api:generate` against `/openapi.json` — stops hiding the credential the code already
honours, and stops omitting two failures the reservation reads already produce.

Decisions in play: D6, D7, D8, D27, D34.

## Step 2.1 — One definition of the credential

**Touch:** `src/modules/special_access/special_access.schema.ts`

**Do:** Append this after `AccessIdParamSchema` (before the `export type` lines):

```ts
/**
 * The credential a link-holder sends, as a QUERY parameter. One definition, spread
 * into every token-enabled route's `request.query` (D6):
 *
 *   request: { query: AccessIdQuerySchema }
 *   request: { query: GetShotsQuerySchema.extend(AccessIdQuerySchema.shape) }
 *
 * It must stay OPTIONAL, and it must never be paired with a route-level
 * `security: [...]` array: the guard is either-or (session OR token) and an
 * OpenAPI `security` entry means "required" (D7).
 */
export const AccessIdQuerySchema = z.object({
  accessId: z
    .string()
    .optional()
    .openapi({
      param: { name: "accessId", in: "query" },
      description:
        "The access link's credential. Supplying it selects the token path — the " +
        "bearer session is then not consulted, not even as a fallback. Omitting it " +
        "(or sending it empty) uses the session path as before.",
      example: "9f1c2b3a4d5e6f708192a3b4c5d6e7f8",
    }),
});
```

Then change the last line of `CreateSpecialAccessSchema`'s chain from
`.openapi("CreateSpecialAccess");` to:

```ts
  .openapi("CreateSpecialAccess", {
    description:
      "Mints one access link. Exactly one subject is required, and which one depends " +
      "on the scope: `inspection_proof` requires `reservationId`, `damage_evidence` " +
      "requires `incidentItemId`, and supplying both is refused. That rule is enforced " +
      "at runtime by `superRefine`, which JSON Schema cannot express — so this document " +
      "shows only `scope` as required, and a `400 VALIDATION_ERROR` is the enforcement.",
  });
```

**Accept:**
- `grep -n "export const AccessIdQuerySchema" src/modules/special_access/special_access.schema.ts` → one line.
- `grep -n "superRefine, which JSON Schema cannot express" src/modules/special_access/special_access.schema.ts` → one line.
- `npm run gate:openapi` → `GATE PASSED` with `ok openapi` green. The gate does **not** print the
  path count (see `00-index.md` §Verified counts); it is 38 before and after this step, because no
  route is added.

**Verify:** `npm run gate:openapi`

## Step 2.2 — Declare the scheme, and deliberately do not require it

**Touch:** `src/index.ts`

**Do:** Insert this immediately **after** the existing `app.doc("/openapi.json", { … });` call and
**before** `app.get("/docs", …)`:

```ts
/**
 * The access-link credential, declared for code generation only. The guard is
 * either-or — a bearer session OR `?accessId=` — and OpenAPI 3.0 cannot express
 * that, so no route carries a `security` array (which would mean "required") and
 * this scheme is a declaration, not a requirement (D7).
 *
 * Registering after `app.doc` is fine: the document is generated per request, not
 * captured at this call.
 */
app.openAPIRegistry.registerComponent("securitySchemes", "specialAccess", {
  type: "apiKey",
  in: "query",
  name: "accessId",
  description:
    "Alternative to a bearer session on the routes that accept an access link. " +
    "Supply it as a query parameter; the session is then ignored entirely.",
});
```

**Accept:**
- `npm run gate:openapi` → `GATE PASSED` with `ok openapi` green (38 paths — `00-index.md`).
- `grep -n "registerComponent(\"securitySchemes\", \"specialAccess\"" src/index.ts` → one line.
- `grep -rn "security:" src/modules/*/*.contract.ts` → **no output** (D7: no route-level
  `security` array anywhere).

**Verify:** `npm run gate:openapi`

**This was verified against the installed dependency versions on 2026-11-26:** registering
`securitySchemes` with this exact object on the real app produced
`components.securitySchemes.specialAccess = {"type":"apiKey","in":"query","name":"accessId"}`
in the rendered document. The Accept above is the regression check.

## Step 2.4 — Pin the rendered document

**Touch:** `src/modules/special_access/special_access.document.test.ts` (new)

**Do:** Create the file with exactly this content:

```ts
import { describe, it, expect } from "vitest";
import app from "@/index";

/**
 * The document at `/openapi.json` IS the frontend's contract — `covera` runs
 * `npm run api:generate` against it. Nothing else in the suite asserts the
 * RENDERED shape: `check-contracts.ts` reads the contract source, and
 * `npm run gate` never builds the document.
 *
 * `app` is imported, not rebuilt, for the same reason `bootstrap.test.ts`
 * imports it: a throwaway copy would keep passing after the real app changed.
 */
interface Operation {
  parameters?: { name: string; in: string }[];
  security?: unknown;
}

interface Doc {
  components?: {
    securitySchemes?: Record<string, { type?: string; in?: string; name?: string }>;
  };
  paths?: Record<string, Record<string, Operation>>;
}

/** Paths are keyed by path STRING, so `method` is part of every assertion. */
const TOKEN_ENABLED: Array<[string, string]> = [
  ["/reservations/{id}", "get"],
  ["/reservations/{id}/photos", "get"],
  ["/apartments/{id}", "get"],
  ["/apartment-shots/apartment/{apartmentId}", "get"],
  ["/inspections/reservation/{reservationId}", "get"],
  ["/inspections", "post"],
];

const fetchDoc = async (): Promise<Doc> => {
  const res = await app.request("/openapi.json");

  expect(res.status).toBe(200);

  return (await res.json()) as Doc;
};

const queryNames = (doc: Doc, path: string, method: string): string[] =>
  (doc.paths?.[path]?.[method]?.parameters ?? [])
    .filter((parameter) => parameter.in === "query")
    .map((parameter) => parameter.name);

describe("the document declares the access credential", () => {
  it("registers specialAccess as an apiKey carried in the query", async () => {
    const doc = await fetchDoc();

    expect(doc.components?.securitySchemes?.specialAccess).toMatchObject({
      type: "apiKey",
      in: "query",
      name: "accessId",
    });
  });

  it("marks no operation as REQUIRING that scheme (D7)", async () => {
    const doc = await fetchDoc();

    for (const [path, operations] of Object.entries(doc.paths ?? {})) {
      for (const [method, operation] of Object.entries(operations)) {
        expect(
          operation.security,
          `${method.toUpperCase()} ${path} must not declare security`,
        ).toBeUndefined();
      }
    }
  });

  it.each(TOKEN_ENABLED)(
    "declares accessId as a query parameter on %s %s",
    async (path, method) => {
      const doc = await fetchDoc();

      expect(queryNames(doc, path, method)).toContain("accessId");
    },
  );
});
```

**Accept:**
- `npm run gate` → `GATE PASSED`, and the test count is the baseline **+ 8** (two scheme tests
  plus six parameterised cases).
- `grep -c "TOKEN_ENABLED" src/modules/special_access/special_access.document.test.ts` → `2`.

**Verify:** `npm run gate`

**If a `it.each` case fails**, the path string is wrong — read it from the failure message rather
than guessing. The strings above were read off the live document on 2026-11-26.
