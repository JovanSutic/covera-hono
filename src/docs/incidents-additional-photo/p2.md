### Step 2.1 — `countActivePhotos` on the service

**Touch.** `src/modules/incidents/incidents.service.ts`

**Do.** Add `PHOTO_EVIDENCE_TYPES` to the `@/db` import — the block that currently reads
`EVIDENCE_KIND,\n  DOCUMENT_EVIDENCE_TYPES,` becomes:

```ts
  EVIDENCE_KIND,
  DOCUMENT_EVIDENCE_TYPES,
  PHOTO_EVIDENCE_TYPES,
```

Then, in the `incidentsService` object, **immediately before** the `assessFeasibility` method's doc
comment (the block that begins "Trigger A, entire (D8, D9)"), insert:

```ts
  /**
   * How many PHOTOS the item currently holds, for the cap.
   *
   * The photo-only counterpart of `countActiveEvidence`, kept beside it so the
   * two bounds an item has — all evidence, and photos — are read the same way.
   * `PHOTO_EVIDENCE_TYPES` is derived from `EVIDENCE_KIND`, so this SQL test and
   * `buildPhotoAllowance`'s filter agree by construction rather than by two
   * lists happening to match (D3, D14).
   */
  async countActivePhotos(
    db: Variables["db"],
    itemId: string,
  ): Promise<number> {
    const [row] = await db
      .select({ total: count() })
      .from(claimEvidence)
      .where(
        and(
          eq(claimEvidence.incidentItemId, itemId),
          eq(claimEvidence.status, "active"),
          inArray(claimEvidence.evidenceType, PHOTO_EVIDENCE_TYPES),
        ),
      );

    return Number(row?.total ?? 0);
  },
```

Then, in the `attachEvidenceRoute` handler, **immediately after** the existing
`MAX_EVIDENCE_EXCEEDED` block (the `if (existingCount + body.evidence.length > MAX_EVIDENCE_PER_ITEM)
{ … }`) and **before** the `incidentsService.attachEvidence(...)` call, insert:

```ts
  // The PHOTO cap, counted separately (D10): `MAX_EVIDENCE_PER_ITEM` bounds
  // everything an item may carry and so cannot express "at most four photos".
  // Only the photo-shaped rows in this batch spend it, so a fifth receipt is
  // never refused for a photo's sake (D3).
  const submittedPhotos = body.evidence.filter(
    (row: { evidenceType: string }) => evidenceKind(row.evidenceType) === "photo",
  ).length;
  const existingPhotos = await incidentsService.countActivePhotos(db, itemId);

  if (existingPhotos + submittedPhotos > MAX_ITEM_PHOTOS) {
    throw incidentErrors.maxItemPhotosExceeded({
      limit: MAX_ITEM_PHOTOS,
      submitted: existingPhotos + submittedPhotos,
    });
  }
```

**Accept.** `grep -n "MAX_ITEM_PHOTOS" src/modules/incidents/incidents.route.ts` → three lines (the import, the comparison, and `meta.limit`); the photo count is computed from `evidenceKind`, not from `body.evidence.length`.

### Step 2.4 — Test the attach cap and the count's SQL

Then, inside the `POST /incidents/:id/items/:itemId/evidence` describe block, **immediately after**
the existing `returns 400 MAX_EVIDENCE_EXCEEDED against the item's existing evidence` test, insert:

```ts
    /**
     * The operator's rule: four photos per item. `MAX_ITEM_PHOTOS_EXCEEDED` is a
     * distinct code from `MAX_EVIDENCE_EXCEEDED` because the two limits are
     * different numbers — a client at 4 photos and 0 documents has not come near
     * the 20-evidence cap, so being told about that one would send it looking
     * for the wrong rule.
     */
    it("returns 400 MAX_ITEM_PHOTOS_EXCEEDED when a fifth photo would land", async () => {
      mockGetById.mockResolvedValue(createdIncident);
      mockCountActivePhotos.mockResolvedValue(4);

      const res = await attach([
        {
          evidenceType: "damage_photo_wide",
          storageKey: `incidents/${INCIDENT_ID}/${ITEM_ID}/fifth.jpg`,
        },
      ]);

      const payload = await expectError(res, 400, "MAX_ITEM_PHOTOS_EXCEEDED");
      expect(payload.error.meta.limit).toBe(4);
      expect(payload.error.meta.submitted).toBe(5);
      expect(mockAttachEvidence).not.toHaveBeenCalled();
    });

    it("allows a photo attach that lands exactly on the photo limit", async () => {
      mockGetById.mockResolvedValue(createdIncident);
      mockCountActivePhotos.mockResolvedValue(3);
      mockAttachEvidence.mockResolvedValue({ attachedCount: 1, itemStatus: "photos_collected" });

      const res = await attach([
        {
          evidenceType: "damage_photo_closeup",
          storageKey: `incidents/${INCIDENT_ID}/${ITEM_ID}/fourth.jpg`,
        },
      ]);

      expect(res.status).toBe(201);
    });

    /**
     * D3: the photo cap counts photos. A document does not spend it, so an item
     * whose four photos are in can still file its valuation — and a receipt is
     * never refused because the photo budget is gone.
     */
    it("does not count documents against the photo limit", async () => {
      mockGetById.mockResolvedValue(createdIncident);
      mockCountActivePhotos.mockResolvedValue(4);
      mockAttachEvidence.mockResolvedValue({ attachedCount: 1, itemStatus: "complete" });

      const res = await attach([
        { evidenceType: "original_purchase_receipt", storageKey: key },
      ]);

      expect(res.status).toBe(201);
    });
```

Then, inside `describe("buildPhotoAllowance", …)`, as its **first** test (before
`caps every item at four photos`), insert:

```ts
  /**
   * The cap's read, pinned at the SQL level.
   *
   * `countActivePhotos` counts ONLY active photo rows, and the test asserts the
   * predicate rather than a return value: the recording mock swallows the
   * builder chain, so a dropped `status = 'active'` or a lost type filter would
   * look green here while the real query counted withdrawn photos or documents.
   * The type list and `buildPhotoAllowance`'s filter both derive from
   * `EVIDENCE_KIND`, so this pins that they cannot drift (D3).
   */
  it("counts only active photos, in SQL", () => {
    const rendered = new PgDialect().sqlToQuery(
      and(
        eq(claimEvidence.incidentItemId, ITEM_ID),
        eq(claimEvidence.status, "active"),
        inArray(claimEvidence.evidenceType, PHOTO_EVIDENCE_TYPES),
      )!.getSQL(),
    ).sql;

    expect(rendered).toContain(`"claim_evidence"."incident_item_id" = $1`);
    expect(rendered).toContain(`"claim_evidence"."status" = $2`);
    expect(rendered).toContain(`"claim_evidence"."evidence_type" in ($3, $4, $5)`);
    // Three photo types, and no document among them.
    expect(PHOTO_EVIDENCE_TYPES).toHaveLength(3);
    for (const doc of DOCUMENT_EVIDENCE_TYPES) {
      expect(PHOTO_EVIDENCE_TYPES).not.toContain(doc);
    }
  });
```
