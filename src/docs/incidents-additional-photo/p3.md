### Step 3.1 — Carry the allowance in the field guidance

**Touch.** `src/modules/incidents/incidents.service.ts`, `src/modules/incidents/incidents.schema.ts`

**Do.** In `getFieldEvidenceGuidance`, extend the declared return type and the returned object. The
method must read exactly:

```ts
  async getFieldEvidenceGuidance(
    db: Variables["db"],
    itemId: string,
    itemType: "damage" | "theft",
  ): Promise<{
    requiredEvidenceTypes: string[];
    attachedEvidenceCounts: Record<string, number>;
    photoAllowance: PhotoAllowance;
  }> {
    const rows = await db
      .select({ evidenceType: claimEvidence.evidenceType })
      .from(claimEvidence)
      .where(
        and(
          eq(claimEvidence.incidentItemId, itemId),
          eq(claimEvidence.status, "active"),
        ),
      );

    const counts: Record<string, number> = {};
    for (const row of rows as Array<{ evidenceType: string }>) {
      counts[row.evidenceType] = (counts[row.evidenceType] ?? 0) + 1;
    }

    return {
      requiredEvidenceTypes: requiredPhotoTypes(itemType),
      attachedEvidenceCounts: counts,
      // The same derived rule the host payload and the writes use, so the field
      // page offers exactly as many photos as the submit will accept — three
      // integers and a cap, which is safe on the unauthenticated surface (D9).
      photoAllowance: buildPhotoAllowance(itemType, rows as Array<{ evidenceType: string }>),
    };
  },
```

The rows read here are already filtered to `status = 'active'`, which is exactly what
`buildPhotoAllowance` expects (D7) — the query needs no second filter.

In `incidents.schema.ts`, add the field to `FieldIngestSchema` **after** `attachedEvidenceCounts`:

```ts
    requiredEvidenceTypes: z.array(z.string()),
    attachedEvidenceCounts: z.record(z.string(), z.number().int()),
    photoAllowance: PhotoAllowanceSchema,
    tokenExpiresAt: z.string().datetime(),
```

**Accept.** `grep -n "photoAllowance" src/modules/incidents/incidents.schema.ts` → two lines (the `IncidentItemBaseSchema` key from phase 1 and the `FieldIngestSchema` key); `npx tsc --noEmit` → exit 0.

### Step 3.3 — Enforce the cap on the field submit

**Touch.** `src/modules/incidents/incidents.field.route.ts`, `src/modules/incidents/incidents.field.contract.ts`

**Do.** In `incidents.field.route.ts`, add `MAX_ITEM_PHOTOS` to the service import block, which must
read:

```ts
import {
  incidentsService,
  requiredPhotoTypes,
  MAX_EVIDENCE_PER_ITEM,
  MAX_ITEM_PHOTOS,
} from "./incidents.service";
```

Then, in the `submitFieldEvidenceRoute` handler, **immediately after** the existing
`MAX_EVIDENCE_EXCEEDED` block and **before** the `incidentsService.submitFieldEvidence(...)` call,
insert:

```ts
  // The PHOTO cap (D10). Every photo here is a photo by construction — the field
  // submit accepts no documents — so the batch size itself is what is counted
  // against the item's existing photos. Same rule the host attach enforces, so
  // the field page's `photoAllowance` and this refusal cannot disagree.
  const existingPhotos = await incidentsService.countActivePhotos(
    db,
    context.item.id,
  );

  if (existingPhotos + body.photos.length > MAX_ITEM_PHOTOS) {
    throw incidentErrors.maxItemPhotosExceeded({
      limit: MAX_ITEM_PHOTOS,
      submitted: existingPhotos + body.photos.length,
    });
  }
```

In `incidents.field.contract.ts`, replace the `fieldSubmitErrors` bundle with:

```ts
const fieldSubmitErrors = errorResponses([
  ...VALIDATION,
  "FIELD_TOKEN_INVALID",
  "EVIDENCE_TYPE_MISMATCH",
  // Named because the handler throws them: `check-contracts.ts` only requires
  // the statuses a GUARD implies, so a handler-thrown 400 is otherwise invisible
  // here and the document would omit failures the route really produces (D15).
  "EVIDENCE_KEY_INVALID",
  "MAX_EVIDENCE_EXCEEDED",
  "MAX_ITEM_PHOTOS_EXCEEDED",
  "INTERNAL_SERVER_ERROR",
]);
```

**Accept.** `grep -n "MAX_ITEM_PHOTOS" src/modules/incidents/incidents.field.route.ts src/modules/incidents/incidents.field.contract.ts` → three lines in the route (import, comparison, `meta.limit`) and one in the contract; `npx tsx scripts/check-contracts.ts` → exit 0.
