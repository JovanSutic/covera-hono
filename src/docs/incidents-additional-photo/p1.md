### Step 1.3 — `MAX_ITEM_PHOTOS` and `buildPhotoAllowance`

**Touch.** `src/modules/incidents/incidents.service.ts`

**Do.** **Immediately after** the `MAX_EVIDENCE_PER_ITEM` declaration and its doc comment, insert:

```ts
/**
 * The per-item PHOTO cap.
 *
 * The operator's rule: at most four photos per item, whatever the asset's
 * requirement — a `damage` item needs two shots and may add two more, a `theft`
 * item needs one and may add three. The required shots are the minimum the
 * cleaner is prompted for, not a lower cap, which is why the ceiling does not
 * vary by type.
 *
 * Counted separately from `MAX_EVIDENCE_PER_ITEM`, which bounds EVERYTHING an
 * item may carry and therefore cannot express "four photos" — and which must
 * keep counting documents, so a receipt is never refused for a photo's sake
 * (D3, D4).
 */
export const MAX_ITEM_PHOTOS = 4;
```

**Then**, in the same file, **immediately before** the `withKind` helper (the `const withKind = …`
declaration that begins "Adds the derived `kind` to an evidence row"), insert:

```ts
/**
 * How many photos an item may hold, and how much room is left.
 *
 * One function for every surface: the host item payload, the field page and the
 * two writes that enforce the cap all read this, so none of them can disagree
 * about the same item's headroom — the failure mode being a client that offers
 * a fifth photo the write then refuses (D6).
 *
 * `evidence` is expected to be the ACTIVE rows, as every caller already filters
 * them through `activeEvidence`: a withdrawn photo must give its slot back
 * (D7). The photo half comes from `EVIDENCE_KIND` via `evidenceKind`, the same
 * map `recomputeItemStatus` trusts, so adding an enum member cannot leave this
 * counting a stale list.
 */
export const buildPhotoAllowance = (
  type: "damage" | "theft",
  evidence: ReadonlyArray<{ evidenceType: string }>,
): PhotoAllowance => {
  const attached = evidence.filter(
    (row) => evidenceKind(row.evidenceType) === "photo",
  ).length;

  return {
    max: MAX_ITEM_PHOTOS,
    required: requiredPhotoTypes(type).length,
    attached,
    remaining: Math.max(0, MAX_ITEM_PHOTOS - attached),
  };
};
```

**Then** add `photoAllowance` to the type-only import from `./incidents.schema` — the import block
that currently ends `UpdateIncidentItem,\n} from "./incidents.schema";` — by inserting this line
before the closing brace:

```ts
  PhotoAllowance,
```

**Accept.** `npx tsc --noEmit` → exit 0 (the helper compiles and `PhotoAllowance` resolves).

### Step 1.5 — Test the allowance and its four sites

**Touch.** `src/modules/incidents/incidents.service.test.ts`, `src/modules/incidents/incidents.test.ts`

**Do.** In `incidents.service.test.ts`, add `buildPhotoAllowance` and `MAX_ITEM_PHOTOS` to the
existing import list from `./incidents.service` (the block that already imports
`requiredPhotoTypes`, `MAX_EVIDENCE_PER_ITEM`, …). Then **immediately before** the existing
`describe("constants", () => {` block, insert:

```ts
describe("buildPhotoAllowance", () => {
  const photo = (evidenceType: string) => ({ evidenceType, status: "active" });

  it("caps every item at four photos, whatever it requires", () => {
    expect(buildPhotoAllowance("damage", []).max).toBe(4);
    expect(buildPhotoAllowance("theft", []).max).toBe(4);
  });

  /**
   * The operator's arithmetic: the requirement is what the cleaner is prompted
   * for, so a `damage` item (2 required) may add 2 more and a `theft` item
   * (1 required) may add 3. Both land on 4.
   */
  it("reports the required shots per type as advisory guidance", () => {
    expect(buildPhotoAllowance("damage", []).required).toBe(2);
    expect(buildPhotoAllowance("theft", []).required).toBe(1);
  });

  it("counts only photos, so documents do not spend the allowance", () => {
    const allowance = buildPhotoAllowance("damage", [
      photo("damage_photo_wide"),
      photo("original_purchase_receipt"),
      photo("handyman_invoice"),
      photo("police_report"),
    ]);

    expect(allowance.attached).toBe(1);
    expect(allowance.remaining).toBe(3);
  });

  it("reduces the remaining count as photos accumulate", () => {
    const allowance = buildPhotoAllowance("damage", [
      photo("damage_photo_wide"),
      photo("damage_photo_wide"),
      photo("damage_photo_closeup"),
      photo("damage_photo_closeup"),
    ]);

    expect(allowance.attached).toBe(4);
    expect(allowance.remaining).toBe(0);
  });

  /**
   * `remaining` never goes negative: the write refuses a fifth photo, but a read
   * of an item that somehow holds more must still report a number a UI can use
   * as a count rather than a negative.
   */
  it("floors remaining at zero", () => {
    const allowance = buildPhotoAllowance("theft", [
      photo("theft_empty_space_photo"),
      photo("theft_empty_space_photo"),
      photo("theft_empty_space_photo"),
      photo("theft_empty_space_photo"),
      photo("theft_empty_space_photo"),
    ]);

    expect(allowance.attached).toBe(5);
    expect(allowance.remaining).toBe(0);
  });
});
```
