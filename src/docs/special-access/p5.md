The steps below state what each change is, so a reviewer can read the phase without opening the
reference. **Where a step's change and its reference file disagree, the reference file is what was
tested — prefer it and report the disagreement.**

Every step replaces a route's existing `middleware` array. The **only** thing that may change is
that array, plus the route's error bundle gaining the two new 403 codes. Handler bodies, paths,
request schemas and success shapes are untouched — that is what keeps D5 true.

`roles` is passed **only** where the route already had a `rolesGuard`. `GET /apartments/{id}` has
none, so its step omits the argument, costing it nothing.

### Step 5.1 — `GET /reservations/{id}` and `GET /reservations/{id}/photos`

Both routes already mount `[authGuard, rolesGuard(["admin", "host"])]` and both are bound by the
same path param `id`, so they are one step.

**Touch.** `src/modules/reservations/reservations.contract.ts` (edit)

**Do.** Add the import beside the existing guard imports:

```ts
import { specialAccessGuard } from "@/middleware/specialAccessGuard";
```

In `getReservationByIdRoute` and in `getReservationPhotosRoute`, replace the `middleware` line:

```ts
  middleware: [authGuard, rolesGuard(["admin", "host"])] as const,
```

with:

```ts
  middleware: [
    specialAccessGuard({
      scope: "inspection_proof",
      bind: { kind: "reservationParam", param: "id" },
      roles: ["admin", "host"],
    }),
  ] as const,
```

Then extend `getReservationByIdErrors`, which both routes already spread, with the two new codes:

```ts
const getReservationByIdErrors = errorResponses([
  ...AUTHED,
  ...ROLE,
  ...VALIDATION,
  "SPECIAL_ACCESS_INVALID",
  "SPECIAL_ACCESS_SCOPE_MISMATCH",
  "RESERVATION_NOT_FOUND",
  "APARTMENT_NOT_FOUND",
  "FORBIDDEN_APARTMENT_ACCESS",
]);
```

**Accept.** `npm run gate` → exit 0; `npx vitest run src/modules/reservations` → **26** tests passing, with **no test file edited**

**Verify.** `npm run gate`

### Step 5.2 — `GET /apartments/{id}`

This route mounts `authGuard` **alone** today. `roles` is deliberately omitted so the guard
reproduces that exactly — adding a role check here would 403 a `guest` who can read an apartment
right now.

**Touch.** `src/modules/apartments/apartments.contract.ts` (edit)

**Do.** Add the import:

```ts
import { specialAccessGuard } from "@/middleware/specialAccessGuard";
```

In `getApartmentByIdRoute`, replace:

```ts
  middleware: [authGuard] as const,
```

with:

```ts
  middleware: [
    specialAccessGuard({
      scope: "inspection_proof",
      bind: { kind: "apartmentParam", param: "id" },
    }),
  ] as const,
```

and extend its bundle — **without** `...ROLE`:

```ts
const getApartmentByIdErrors = errorResponses([
  ...AUTHED,
  "SPECIAL_ACCESS_INVALID",
  "SPECIAL_ACCESS_SCOPE_MISMATCH",
  ...VALIDATION,
  "APARTMENT_NOT_FOUND",
]);
```

`...ROLE` is deliberately **not** added. The guard can produce `FORBIDDEN_ROLE` on routes that
pass `roles`, but this route passes none, so a role check never runs and this route cannot produce
that status. Declaring it would document a failure the route does not have. `check-contracts.ts`
requires a 403 only when it can see `rolesGuard`/`apartmentGuard` in the middleware text, and it
cannot see either here (`specialAccessGuard` contains neither substring) — the two
`SPECIAL_ACCESS_*` codes supply the 403 the contract needs.

**Accept.** `npm run gate` → exit 0 (the contracts check passing proves the 403 is declared
without `...ROLE`); `npx vitest run src/modules/apartments` → **15** tests passing, no test edited

**Verify.** `npm run gate`

### Step 5.6 — Prove the six routes open with a token, and are unchanged without one

The per-module suites (steps 5.1–5.5) already prove the **no-token** half, because they are
unmodified and still pass. What they cannot show is that a token actually opens each route. This
step adds that, plus the one assertion no other suite makes: that an unmodified existing test still
describes the no-token path.

**Touch.** `src/modules/inspections/inspections.test.ts` (edit)

**Do.** The verified file is [`reference/wired-inspections.test.ts.txt`](./reference/wired-inspections.test.ts.txt)
— copy that, which is this step plus steps 5.4/5.5 already applied. What it adds to the original:

1. A **static** import beside the existing ones (not a dynamic `await import` — under `NodeNext`,
   a dynamic `@/…` import resolves in ESM mode and demands a `.js` extension, which fails
   `tsc`; the alias therefore cannot be used dynamically here):

```ts
import { specialAccessService } from "../special_access/special_access.service";
```

2. The matching mock, beside the file's existing `vi.mock` calls:

```ts
vi.mock("../special_access/special_access.service", () => ({
  specialAccessService: {
    resolveByToken: vi.fn(),
    resolveApartmentOwner: vi.fn(),
  },
}));
```

3. A `describe` block at the end of the file with three cases:

- `"opens GET /reservation/{reservationId} with a valid token and no session"` — mocks a valid
  grant and asserts **200**, with no `Authorization` header on the request.
- `"refuses a token minted for a DIFFERENT reservation"` — asserts **403
  `SPECIAL_ACCESS_SCOPE_MISMATCH`**, the assertion no other suite makes.
- `"still requires a session when no token is supplied"` — asserts **401**.

It reuses the file's own `testApp`, `mockCheckExistence` and `mockGetByReservationId`; use those
names rather than introducing new ones.

**Accept.** `npx vitest run src/modules/inspections` → **19** tests passing (16 pre-existing + 3 new); `npm run gate:openapi` → **782** tests passing, exit 0

**Verify.** `npm run gate`

## Phase 5 invariants

- [ ] Each of the six routes is opened by `specialAccessGuard` **alone** — no route lists both the
      guard and `authGuard`/`rolesGuard`
- [ ] `roles` is passed on exactly the five routes that had a `rolesGuard`; **not** on
      `GET /apartments/{id}`
- [ ] Each route's error bundle declares `SPECIAL_ACCESS_INVALID` and `SPECIAL_ACCESS_SCOPE_MISMATCH`
- [ ] No handler body changed; no path, request schema or success shape changed
- [ ] No existing test file was edited to accommodate the guard (step 5.6 only appends)
- [ ] `POST /inspections/{id}/flags` and `PUT /apartment-shots/apartment/{apartmentId}` are untouched
