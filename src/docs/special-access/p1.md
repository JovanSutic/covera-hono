### Step 1.1 — Create the `special_access` table and its scope enum

**Touch.** `src/db/schema/special-access.ts` (create)

**Do.** The **tested** version of this file is
[`reference/db-special-access.ts.txt`](./reference/db-special-access.ts.txt) — it was built and the
gate run green on it, so **copy that file verbatim and let it win over the block below if the two
disagree**. The block below is the same code written out in expanded form; it is here so a reviewer
can read the step without opening the reference, not as a second source of truth.

The one thing the block below must NOT carry into the file: the `unique` import is unused (the
column-level `.unique()` on `accessId` is what creates the constraint), and `@typescript-eslint/no-unused-vars`
is configured as a *warning*, so an unused import slips through `gate`'s `eslint --quiet` and lands
as dead text. The reference omits it.

```ts
import {
  pgTable,
  pgEnum,
  uuid,
  varchar,
  timestamp,
  index,
  unique,
  check,
} from "drizzle-orm/pg-core";
import { sql } from "drizzle-orm";
import { relations, InferInsertModel, InferSelectModel } from "drizzle-orm";
import { createInsertSchema, createSelectSchema } from "drizzle-zod";
import { apartments } from "./apartments";
import { reservations } from "./reservations";
import { incidentItems } from "./incident-items";
import { users } from "./users";

/**
 * The named instances of special access (D1). One value per group of resources
 * that a link may open; adding a third is a new enum value plus a registry row in
 * `SCOPE_TARGETS` in the guard, not a new mechanism.
 */
export const accessScopeEnum = pgEnum("access_scope", [
  "inspection_proof",
  "damage_evidence",
]);

/**
 * A time-limited, resource-scoped grant a host mints and shares as a link.
 *
 * `access_id` is the credential and is deliberately NOT the primary key (D2): a
 * re-minted link must be a new row, and the FK targets must stay stable.
 *
 * The subject columns are per-scope and the CHECK below is what keeps them
 * honest — `inspection_proof` binds a reservation, `damage_evidence` binds an
 * incident item. `apartment_id` is denormalized from the subject (D12) so the two
 * apartment-scoped routes need no join on redemption.
 *
 * FKs CASCADE from the subject (a grant for a deleted reservation is
 * meaningless) and SET NULL from `created_by` (the grant outlives the host's
 * account, and the audit trail is worth keeping).
 */
export const specialAccess = pgTable(
  "special_access",
  {
    id: uuid("id").primaryKey().defaultRandom(),

    accessId: varchar("access_id", { length: 64 }).notNull().unique(),

    scope: accessScopeEnum("scope").notNull(),

    apartmentId: uuid("apartment_id")
      .notNull()
      .references(() => apartments.id, { onDelete: "cascade" }),

    reservationId: uuid("reservation_id").references(() => reservations.id, {
      onDelete: "cascade",
    }),

    incidentItemId: uuid("incident_item_id").references(() => incidentItems.id, {
      onDelete: "cascade",
    }),

    expiresAt: timestamp("expires_at", { withTimezone: true }).notNull(),

    revokedAt: timestamp("revoked_at", { withTimezone: true }),
    usedAt: timestamp("used_at", { withTimezone: true }),

    createdBy: uuid("created_by").references(() => users.id, {
      onDelete: "set null",
    }),

    createdAt: timestamp("created_at", { withTimezone: true })
      .defaultNow()
      .notNull(),
  },
  (table) => [
    index("idx_special_access_reservation").on(table.reservationId),
    index("idx_special_access_incident_item").on(table.incidentItemId),
    check(
      "special_access_subject_matches_scope",
      sql`(${table.scope} = 'inspection_proof' AND ${table.reservationId} IS NOT NULL AND ${table.incidentItemId} IS NULL)
       OR (${table.scope} = 'damage_evidence' AND ${table.incidentItemId} IS NOT NULL)`,
    ),
  ],
);
```

The `accessId` column carries `.unique()` and **no** named `unique(...)` constraint is added in the
table extras: declaring both collapses to one constraint named after the column, so the second
declaration is dead text. `incident_items.cleaner_token` — the shape being mirrored — uses the
column-level form.

The same file continues with the relational definitions, the base Zod schemas and the exported
types:

```ts
// 3. Drizzle Relational Definitions
export const specialAccessRelations = relations(specialAccess, ({ one }) => ({
  apartment: one(apartments, {
    fields: [specialAccess.apartmentId],
    references: [apartments.id],

    fields: [specialAccess.reservationId],
    references: [reservations.id],
  }),
  incidentItem: one(incidentItems, {
    fields: [specialAccess.incidentItemId],
    references: [incidentItems.id],
  }),
  creator: one(users, {
    fields: [specialAccess.createdBy],
    references: [users.id],
  }),

// 4. Base Zod Schemas
export const SelectSpecialAccessSchema = createSelectSchema(specialAccess);
export const InsertSpecialAccessSchema = createInsertSchema(specialAccess);

// 5. Types
export type SpecialAccess = InferSelectModel<typeof specialAccess>;
export type NewSpecialAccess = InferInsertModel<typeof specialAccess>;
export type AccessScope = (typeof accessScopeEnum.enumValues)[number];
```

### Step 1.6 — Record the codes in the registry-of-record

**Touch.** `src/docs/errorHandle.md` (edit)

**Do.** In §5's table, add `SPECIAL_ACCESS_INVALID`, `SPECIAL_ACCESS_SCOPE_MISMATCH` to the **403**
row and `SPECIAL_ACCESS_NOT_FOUND` to the **404** row. Then append a new section at the end of the
document:

```md
---

## 12. Token failures reuse 403, not 404

`src/docs/special-access.decisions.md` D8. Every other token-only surface in this API — the
`/field/ingest` link — answers `404 FIELD_TOKEN_INVALID`, because there the token *is* the whole
path and a 404 therefore confirms nothing about any other resource.

The `?accessId=` routes are different: their path already names a real resource id. Answering 404
for a bad token there would make "this link has expired" indistinguishable from "this reservation
no longer exists" — two conditions with different remedies. They answer **403** instead, which is
also what `roleGuard` already answers for "your credential does not open this". That is safe only
because the token is validated *before* the target is resolved (D9), so the response is a statement
about the caller's own credential and nothing else.
```

**Accept.** `grep -c "SPECIAL_ACCESS_INVALID\|SPECIAL_ACCESS_SCOPE_MISMATCH\|SPECIAL_ACCESS_NOT_FOUND" src/docs/errorHandle.md` → `3`

**Verify.** `npm run gate`

### Step 1.7 — Test the registry additions

The three codes are already covered by the file's own `it.each(CODES)` blocks — reachability,
description shape, envelope round-trip, and message copy all iterate the registry, so the new codes
are picked up with no edit. This step adds only the two properties those generic blocks cannot
express.

**Touch.** `src/core/errors/error.codes.test.ts` (edit)

**Do.** Insert this block immediately **before** the
`it("expects a status for every registered code, and no others", …)` declaration, inside the
existing top-level `describe`:

```ts
  describe("special access codes", () => {
    const SPECIAL_ACCESS_CODES = [
      "SPECIAL_ACCESS_INVALID",
      "SPECIAL_ACCESS_SCOPE_MISMATCH",
      "SPECIAL_ACCESS_NOT_FOUND",
    ] as const;

    // Invariant 7: these codes describe the caller's credential and nothing
    // about the resource. A description echoing the token or a reservation id
    // would turn a 403 into a resource-existence oracle.
    it("names no id, target, or token in any special-access description", () => {
      for (const code of SPECIAL_ACCESS_CODES) {
        const description = ERROR_REGISTRY[code].description;
        expect(description).not.toMatch(/[0-9a-f]{8}-[0-9a-f]{4}/i);
        expect(description).not.toMatch(/accessId|access_id/i);
      }
    });

    // D8, written out so a later status flip is a reviewable diff rather than a
    // silent client-facing break.
    it("keeps token failures on 403 and grant lookups on 404", () => {
      expect(ERROR_REGISTRY.SPECIAL_ACCESS_INVALID.status).toBe(403);
      expect(ERROR_REGISTRY.SPECIAL_ACCESS_SCOPE_MISMATCH.status).toBe(403);
      expect(ERROR_REGISTRY.SPECIAL_ACCESS_NOT_FOUND.status).toBe(404);
    });
  });
```
