# Phase 1 — The three tables

**Prerequisite:** none
**Gate:** `npm run gate`

This phase is almost entirely transcription: the code below has been compiled and generated against
this repo (see the decisions file's "Facts verified" table). Reproduce it verbatim.

Steps 1.1–1.3 create three files that import each other cyclically. That is expected and is exactly
how `inspections.ts` / `inspection-flags.ts` are already arranged — the relations callbacks are
lazy, so the cycle resolves. Group them into one write pass; the group compiles once at the end.

The enums live inline in the table file that uses them, matching `reservations.ts`,
`inspection-flags.ts` and `apartment-images.ts`. `asset-enums.ts` is the shared-file convention and
is for enums used by more than one table; none of these are (D3, and the schema conventions).

### Step 1.1 — Define `incidents`

**Touch.** `src/db/schema/incidents.ts` (create)

**Do.**

```ts
import {
  pgTable,
  pgEnum,
  uuid,
  boolean,
  integer,
  timestamp,
  index,
} from "drizzle-orm/pg-core";
import { relations, InferInsertModel, InferSelectModel } from "drizzle-orm";
import { createInsertSchema, createSelectSchema } from "drizzle-zod";
import { reservations } from "./reservations";
import { incidentItems } from "./incident-items";

// 1. Enums
export const incidentStatusEnum = pgEnum("incident_status", [
  "draft",
  "ready_to_file",
  "submitted_to_guest",
  "escalated_to_aircover",
  "resolved",
  "unfeasible",
]);

// 2. Table Definition
//
// One claim per reservation: `reservation_id` is UNIQUE (the Airbnb 1:1), and
// deleting the reservation takes the claim with it. The reverse is not true of
// `incident_items.asset_id`, which restricts — see incident-items.ts.
export const incidents = pgTable(
  "incidents",
  {
    id: uuid("id").primaryKey().defaultRandom(),

    reservationId: uuid("reservation_id")
      .notNull()
      .unique()
      .references(() => reservations.id, { onDelete: "cascade" }),

    status: incidentStatusEnum("status").default("draft").notNull(),
    isEmergencyMode: boolean("is_emergency_mode").default(false).notNull(),

    // Money is integer cents, matching `assets.approximate_value_cents`.
    placeholderTotalAmountCents: integer("placeholder_total_amount_cents")
      .default(0)
      .notNull(),
    finalPayoutRequestedCents: integer("final_payout_requested_cents")
      .default(0)
      .notNull(),

    resolutionCenterSubmittedAt: timestamp("resolution_center_submitted_at", {
      withTimezone: true,
    }),
    guestResponseDeadlineAt: timestamp("guest_response_deadline_at", {
      withTimezone: true,
    }),
    // Checkout + 30 days, frozen at creation: the deadline the host was shown
    // must not move if the reservation is edited later (D7).
    aircoverEscalationDeadlineAt: timestamp("aircover_escalation_deadline_at", {
      withTimezone: true,
    }).notNull(),

    createdAt: timestamp("created_at", { withTimezone: true })
      .defaultNow()
      .notNull(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .defaultNow()
      .notNull(),
  },
  (table) => [index("idx_incidents_status").on(table.status)],
);

// 3. Drizzle Relational Definitions
export const incidentsRelations = relations(incidents, ({ one, many }) => ({
  reservation: one(reservations, {
    fields: [incidents.reservationId],
    references: [reservations.id],
  }),
  items: many(incidentItems),
}));

// 4. Base Zod Schemas
export const SelectIncidentSchema = createSelectSchema(incidents);
export const InsertIncidentSchema = createInsertSchema(incidents);

// 5. Types
export type Incident = InferSelectModel<typeof incidents>;
export type NewIncident = InferInsertModel<typeof incidents>;
```

### Step 1.2 — Define `incident_items`

**Touch.** `src/db/schema/incident-items.ts` (create)

**Do.**

```ts
import {
  pgTable,
  pgEnum,
  uuid,
  varchar,
  text,
  integer,
  timestamp,
  index,
  unique,
} from "drizzle-orm/pg-core";
import { relations, InferInsertModel, InferSelectModel } from "drizzle-orm";
import { createInsertSchema, createSelectSchema } from "drizzle-zod";
import { incidents } from "./incidents";
import { assets } from "./assets";
import { claimEvidence } from "./claim-evidence";

// 1. Enums
export const assetIncidentTypeEnum = pgEnum("asset_incident_type", [
  "damage",
  "theft",
]);

export const incidentItemStatusEnum = pgEnum("incident_item_status", [
  "link_generated",
  "photos_collected",
  "documents_pending",
  "complete",
]);

// 2. Table Definition
//
// `asset_id` RESTRICTS rather than cascades: an asset named in a claim is the
// evidence the claim rests on, so deleting it must fail loudly instead of
// silently emptying the claim (D5).
//
// `cleaner_token` is UNIQUE and single-use — the submit route expires it (D11).
// `UNIQUE(incident_id, asset_id)` is what makes one asset appear at most once
// per claim; the domain layer asserts it first so the client gets a readable
// error rather than a constraint violation.
export const incidentItems = pgTable(
  "incident_items",
  {
    id: uuid("id").primaryKey().defaultRandom(),

    incidentId: uuid("incident_id")
      .notNull()
      .references(() => incidents.id, { onDelete: "cascade" }),

    assetId: uuid("asset_id")
      .notNull()
      .references(() => assets.id, { onDelete: "restrict" }),

    type: assetIncidentTypeEnum("type").notNull(),
    status: incidentItemStatusEnum("status").default("link_generated").notNull(),

    cleanerToken: varchar("cleaner_token", { length: 64 }).notNull().unique(),
    tokenExpiresAt: timestamp("token_expires_at", {
      withTimezone: true,
    }).notNull(),

    estimatedPlaceholderValueCents: integer("estimated_placeholder_value_cents")
      .default(0)
      .notNull(),
    descriptionByCleaner: text("description_by_cleaner"),

    createdAt: timestamp("created_at", { withTimezone: true })
      .defaultNow()
      .notNull(),
    updatedAt: timestamp("updated_at", { withTimezone: true })
      .defaultNow()
      .notNull(),
  },
  (table) => [
    unique("incident_items_incident_asset_unique").on(
      table.incidentId,
      table.assetId,
    ),
    index("idx_incident_items_incident").on(table.incidentId),
    index("idx_incident_items_asset").on(table.assetId),
  ],
);

// 3. Drizzle Relational Definitions
export const incidentItemsRelations = relations(
  incidentItems,
  ({ one, many }) => ({
    incident: one(incidents, {
      fields: [incidentItems.incidentId],
      references: [incidents.id],
    }),
    asset: one(assets, {
      fields: [incidentItems.assetId],
      references: [assets.id],
    }),
    evidence: many(claimEvidence),
  }),
);

// 4. Base Zod Schemas
export const SelectIncidentItemSchema = createSelectSchema(incidentItems);
export const InsertIncidentItemSchema = createInsertSchema(incidentItems);

// 5. Types
export type IncidentItem = InferSelectModel<typeof incidentItems>;
export type NewIncidentItem = InferInsertModel<typeof incidentItems>;
```

**Accept.** `grep -n "onDelete" src/db/schema/incident-items.ts` → 2 lines, one `"cascade"` (incident)
and one `"restrict"` (asset). `grep -n "unique" src/db/schema/incident-items.ts` → 3 lines (the
import, the `.unique()` on `cleanerToken`, the `unique(...)` constraint).

**Verify.** `npx tsc --noEmit` at the end of the group.

### Step 1.3 — Define `claim_evidence`

**Touch.** `src/db/schema/claim-evidence.ts` (create)

**Do.**

```ts
import {
  pgTable,
  pgEnum,
  uuid,
  text,
  decimal,
  timestamp,
  index,
} from "drizzle-orm/pg-core";
import { relations, InferInsertModel, InferSelectModel } from "drizzle-orm";
import { createInsertSchema, createSelectSchema } from "drizzle-zod";
import { incidentItems } from "./incident-items";

// 1. Enums
//
// `original_purchase_receipt`, `replacement_retail_quote`, `handyman_invoice`
// and `police_report` are the document half of the lifecycle. They are declared
// now so the storage format never changes when that half lands, and nothing in
// this feature writes them (D22).
export const evidenceFileTypeEnum = pgEnum("evidence_file_type", [
  "damage_photo_wide",
  "damage_photo_closeup",
  "theft_empty_space_photo",
  "original_purchase_receipt",
  "replacement_retail_quote",
  "handyman_invoice",
  "police_report",
]);

// 2. Table Definition
//
// `storage_key` is the R2 object key, not a URL, matching
// `apartment_images.storage_key` (D4). UNIQUE makes the confirm step idempotent.
//
// The EXIF columns are written from the submit body's own fields; there is no
// extraction job in this repo (D10).
export const claimEvidence = pgTable(
  "claim_evidence",
  {
    id: uuid("id").primaryKey().defaultRandom(),

    incidentItemId: uuid("incident_item_id")
      .notNull()
      .references(() => incidentItems.id, { onDelete: "cascade" }),

    evidenceType: evidenceFileTypeEnum("evidence_type").notNull(),
    storageKey: text("storage_key").notNull().unique(),

    exifCapturedAt: timestamp("exif_captured_at", { withTimezone: true }),
    exifLatitude: decimal("exif_latitude", { precision: 9, scale: 6 }),
    exifLongitude: decimal("exif_longitude", { precision: 9, scale: 6 }),

    createdAt: timestamp("created_at", { withTimezone: true })
      .defaultNow()
      .notNull(),
  },
  (table) => [index("idx_claim_evidence_item").on(table.incidentItemId)],
);

// 3. Drizzle Relational Definitions
export const claimEvidenceRelations = relations(claimEvidence, ({ one }) => ({
  incidentItem: one(incidentItems, {
    fields: [claimEvidence.incidentItemId],
    references: [incidentItems.id],
  }),
}));

// 4. Base Zod Schemas
export const SelectClaimEvidenceSchema = createSelectSchema(claimEvidence);
export const InsertClaimEvidenceSchema = createInsertSchema(claimEvidence);

// 5. Types
export type ClaimEvidence = InferSelectModel<typeof claimEvidence>;
export type NewClaimEvidence = InferInsertModel<typeof claimEvidence>;
```

### Step 1.6 — Remove the assets drift statement from the migration

**Touch.** `drizzle/0013_*.sql` (edit, the file located in 1.5)

**Do.**

The generated file contains this line, which is **not** part of this feature:

```sql
ALTER TABLE "assets" ALTER COLUMN "asset_type_id" SET NOT NULL;--> statement-breakpoint
```

Delete that entire line, including the trailing `--> statement-breakpoint`. It is pre-existing
drift: `assets.ts` declares `.notNull()` but snapshots `0000`–`0012` never recorded it, so the
generator emits it into whatever migration runs next (verified — see D14 and the decisions file's
facts table). Shipping it would tighten a constraint on a production table as a side effect of an
unrelated feature, and would fail on any existing NULL row.

**Delete nothing else.** The file must still contain: 4 `CREATE TYPE` statements, 3 `CREATE TABLE`
statements, 4 `ADD CONSTRAINT … FOREIGN KEY` statements, 4 `CREATE INDEX` statements, and the
`UNIQUE` constraints for `incidents_reservation_id_unique`, `incident_items_cleaner_token_unique`,
`incident_items_incident_asset_unique` and `claim_evidence_storage_key_unique`.

**Accept.** `grep -c "ALTER TABLE" drizzle/0013_*.sql` → `4` (the four FK constraints only).
`grep -c 'ALTER TABLE "assets"' drizzle/0013_*.sql` → `0`.
`grep -c "CREATE TABLE" drizzle/0013_*.sql` → `3`.
`grep -c "CREATE TYPE" drizzle/0013_*.sql` → `4`.
`grep -c "SET NOT NULL" drizzle/0013_*.sql` → `0`.
